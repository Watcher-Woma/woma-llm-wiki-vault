## 定义

ChatGPT 是 OpenAI 开发的大型语言模型系列，专注于对话任务。GPT（Generative Pre-trained Transformer）架构经过多代迭代，从 GPT-3 到 GPT-4o，再到最新的 o 系列推理模型，已成为提示工程领域的重要基准模型之一。

## 模型演进

| 型号 | 发布时间 | 核心能力 | 提示工程特点 |
|------|----------|----------|--------------|
| **GPT-3.5** | 2022-11 | 基础对话、文本生成 | 简单指令即可 |
| **GPT-4** | 2023-03 | 复杂推理、多模态 | 需要详细上下文 |
| **GPT-4o** | 2024-05 | 实时多模态 | 语音/图像原生支持 |
| **o1/o3** | 2024-09 | 推理、科学问题 | 不需要 CoT，内置思考 |

## 核心特性

### 1. 强项
- **创意写作**：故事、诗歌、营销文案
- **代码生成**：多语言支持，代码解释
- **通用知识**：广泛的世界知识覆盖
- **指令跟随**：对结构化指令响应良好

### 2. 局限性
- **知识截止**：训练数据有时间边界
- **幻觉风险**：可能生成看似合理但错误的信息
- **数学推理**：复杂计算需要外部工具辅助
- **长上下文**：超出窗口时可能出现"迷失"

## 提示工程最佳实践

### 针对 GPT-4+

| 技巧 | 说明 | 示例 |
|------|------|------|
| **详细角色设定** | GPT-4 对角色设定响应良好 | "你是一位资深软件架构师..." |
| **结构化输出** | 使用 Markdown 或 JSON | "以表格形式返回，包含列名..." |
| **思维链（注意模型）** | GPT-4 早期版本需要显式 CoT | "请分步骤思考..." |
| **避免冲突指令** | GPT 对矛盾指令敏感 | 确保前后要求一致 |

### 针对 o1/o3 推理模型

> ⚠️ **重要**：推理模型**不需要** Chain-of-Thought，显式 CoT 可能反而降低性能

```markdown
❌ "请分步骤思考这个问题..."
✅ 直接提出问题，让模型内部推理
```

## API 与产品

### API 产品
| 产品 | 特点 | 适用场景 |
|------|------|----------|
| **GPT-4o** | 最新、多模态、低延迟 | 对话、实时应用 |
| **GPT-4-turbo** | 高性能、成本优化 | 复杂任务 |
| **GPT-3.5-turbo** | 快速、便宜 | 简单任务 |

### 消费产品
- **ChatGPT Plus**：订阅制，获得 GPT-4 访问权
- **ChatGPT Team/Enterprise**：团队/企业版本
- **ChatGPT Plugins**：插件生态（部分已迁移到 GPTs）

## 与其他模型的对比

| 维度 | ChatGPT (GPT-4) | Claude | Gemini |
|------|-----------------|--------|--------|
| **训练数据** | 广泛（多种来源） | 安全优先 | Google 全家桶 |
| **对话风格** | 直接、结构化 | 谨慎、细致 | 事实导向 |
| **代码能力** | 优秀 | 良好 | 良好 |
| **长上下文** | 128K | 200K+ | 1M+ |
| **工具使用** | Function Calling | Tool Use | Function Calling |

## 提示词模板示例

### 创意写作
```markdown
你是一位获奖无数的短篇小说作家，擅长在结尾制造意想不到的反转。
请为以下主题写一个 800 字的短篇故事：

主题：{input}

要求：
- 开篇 100 字内抓住读者注意力
- 至少制造 2 次情节转折
- 结尾必须出人意料但逻辑自洽
- 风格：简洁有力，避免冗余描写
```

### 代码审查
```markdown
你是一位拥有 15 年经验的软件工程师，精通代码安全和性能优化。

任务：审查以下 Python 代码，识别潜在问题

代码：
{code}

请检查：
1. 安全漏洞（注入、认证、加密等）
2. 性能瓶颈
3. 错误处理
4. 代码可维护性

输出格式：发现的问题列表，每个问题包含严重程度、描述和修复建议
```
