## 定义

POWER 框架（**P**urpose + **O**utput + **W**orking + **E**xamples + **R**efinement）是一种强调迭代优化的提示工程方法。该框架由 PromptBuilder 提出，特别适合需要高质量输出的复杂任务，以及那些需要通过反馈循环不断改进的场景。

核心思想：**一次不求完美，通过迭代逐步逼近理想结果。**

## 框架五要素

### 1. Purpose（目的）
明确任务的核心目的和价值。

```
❌ "帮我写一篇文章"
✅ "写一篇能帮助初学者理解股票投资基础的文章，
    让读者读完能开始自己的第一笔投资"
```

**Purpose 的价值**：
- 帮助 AI 理解"为什么要做"比"做什么"更重要
- 在信息模糊时，AI 可以基于目的做合理推断
- 便于评估输出是否真正达成了目标

### 2. Output（输出）
定义期望的输出形式和结构。

| 维度 | 示例 |
|------|------|
| **格式** | "以 Markdown 格式输出"、"包含表格" |
| **结构** | "包含摘要、3 个要点、结论" |
| **长度** | "500 字以内"、"详细到每个步骤" |
| **风格** | "正式报告风格"、"口语化解释" |

### 3. Working（工作区）
提供 AI 思考的上下文空间。

```
Working（可选）：
- 当前对问题的理解："我认为关键在于..."
- 已有的素材："我目前有以下数据..."
- 遇到的困难："我卡在如何量化这个指标..."
```

**Working 的独特价值**：
- 展示 AI 的思考过程
- 便于发现 AI 理解上的偏差
- 建立对话的连续性

### 4. Examples（示例）
提供参考示例，引导期望的输出风格。

```
Examples：
示例 1（正面）：
输入："解释什么是通货膨胀"
输出："通货膨胀就像钱包里的钱在慢慢'缩水'。
      假设去年一个汉堡 20 元，今年 22 元，
      虽然你手里的钱没变，但能买的东西变少了..."

示例 2（避免）：
❌ 不要像学术论文那样列出复杂的数学公式
```

**示例的最佳实践**：
- 提供 1-3 个高质量示例
- 可以包含"避免"示例（反面教材）
- 示例要覆盖不同场景

### 5. Refinement（优化）
明确迭代优化方向。

```
Refinement：
- 优先优化：语言通俗易懂，避免专业术语
- 避免：过于理论化，每个概念必须配例子
- 下一步：如果长度超限，优先删减哪个部分
```

**Refinement 的类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| **质量优化** | 提升准确性、深度 | "增加数据支撑"、"补充风险分析" |
| **风格调整** | 改变表达方式 | "更口语化"、"更专业" |
| **格式调整** | 改变结构呈现 | "增加小标题"、"改成表格" |
| **删减优化** | 精简内容 | "砍掉细节，保留核心" |

## 完整模板

```markdown
## Purpose
[任务的核心目的是什么？为什么重要？]

## Output
[期望的输出形式、结构、长度、风格]

## Working
[当前已有的素材、理解或困惑]

## Examples
[提供 1-3 个参考示例，说明期望的输出风格]
示例 1：[...]
示例 2：[...]
避免示例：[...]

## Refinement
[优化方向：优先优化什么、避免什么、下一步调整方向]
```

## 使用示例

### 示例 1：商业计划书
```markdown
## Purpose
帮助一位首次创业者理解如何撰写商业计划书，
让他/她能够独立完成自己的 BP 初稿。

## Output
一份结构清晰、字数适中（1500 字）的 BP 撰写指南：
- 包含 BP 的 6 个核心组成部分
- 每部分有"为什么重要"的解释
- 每部分有写作要点和常见错误
- 有 1 个完整示例章节

## Working
我了解到这位创业者：
- 有技术背景，不太懂商业术语
- 产品是一个面向学生的时间管理 App
- 正在寻找天使轮融资

## Examples
正面示例（引用的 BP 结构）：
"1. 执行摘要（1页）
   - 痛点、市场规模、解决方案、进展"

避免示例（过于复杂的 BP）：
"包含 20 页财务预测、详细的竞品专利分析..."

## Refinement
- 优先优化：语言通俗，减少商业术语
- 避免：假设读者懂 VC 术语
- 下一步：可以针对"执行摘要"单独展开
```

### 示例 2：代码审查
```markdown
## Purpose
帮助团队识别代码中的安全漏洞和性能问题，
提升代码质量，减少线上故障。

## Output
审查报告，包含：
- 问题列表（按严重程度：Critical/High/Medium）
- 每个问题的：位置、描述、风险、修复建议
- 总结：整体代码质量评级

## Working
被审查代码：[粘贴代码]
技术栈：Python + Django
审查重点：API 安全、数据验证、数据库查询

## Examples
Critical 示例：
"未对用户输入进行 SQL 转义 → 直接拼接 SQL 语句 →
存在 SQL 注入风险 → 使用 ORM 或参数化查询"

避免示例：
"代码风格不一致"、"变量命名不规范"（这些不是 Critical）

## Refinement
- 优先识别：可能导致数据泄露或服务中断的问题
- 避免：将风格问题标为高优先级
- 下一步：如果有 Critical 问题，需要优先修复
```

## 迭代使用模式

POWER 框架特别适合多轮迭代：

```
第一轮：
→ Purpose + Output + Examples
→ 获取初稿

第二轮（基于初稿）：
→ Refinement：需要更简洁/更详细
→ Working：补充对初稿的反馈
→ 获取修订稿

第三轮：
→ 继续 refinement
→ 直到满意
```

## 框架对比

| 框架 | 迭代支持 | 最佳场景 |
|------|----------|----------|
| **POWER** | 强（内置 Refinement） | 需要多轮优化的高质量任务 |
| **RISEN** | 中（Next Steps） | 复杂多步骤任务 |
| **CRAFT** | 弱 | 单次创意/专业任务 |
| **CO-STAR** | 弱 | 一次性内容创作 |

## 最佳实践

1. **Purpose 要回答"为什么"**：明确任务的价值和受益人
2. **Output 要具体可衡量**：格式、结构、长度都要明确
3. **Working 要诚实**：展示真实的困惑比假装理解好
4. **Examples 要精选**：2-3 个高质量示例比一堆平庸示例好
5. **Refinement 要可操作**：避免"更好"，要说"具体哪里改"
