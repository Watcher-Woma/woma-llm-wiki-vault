## 定义

APE 框架（**A**ction + **P**urpose + **E**xpectation）是一种简洁高效的提示设计方法，专注于明确表达用户意图的三个核心要素。相比其他框架，APE 更适合行动导向型任务，强调"做什么"而非"怎么做"。

## 框架三要素

### 1. Action（行动）
**定义**：明确要执行的具体任务或动作。

| ❌ 模糊 | ✅ 清晰 |
|--------|--------|
| "处理这个文档" | "提取并总结这份报告的关键数据" |
| "写点什么" | "撰写一封 200 字的产品介绍邮件" |
| "帮我看看" | "审查以下代码的安全漏洞" |

### 2. Purpose（目的）
**定义**：说明任务背后的目的或意图。

```
目的说明的重要性：
- 帮助 AI 理解"为什么"比"做什么"更关键
- 激发 AI 提供更有针对性的解决方案
- 便于 AI 在模糊场景下做出合理假设
```

**示例**：
- "目的是向非技术背景的投资者解释技术方案"
- "目的是准备下周的路演，需要简洁有力"

### 3. Expectation（期望）
**定义**：明确期望的输出结果和标准。

| 维度 | 示例 |
|------|------|
| **格式** | "以表格形式返回"、"不超过 500 字" |
| **风格** | "专业但不刻板"、"口语化但不失权威" |
| **受众** | "面向技术团队"、"面向 CEO" |
| **质量标准** | "每个观点需要数据支撑" |

## 框架对比

| 框架 | 要素数 | 核心关注点 | 适用场景 |
|------|--------|-----------|----------|
| **APE** | 3 | 行动导向 | 快速任务、执行指令 |
| **CRAFT** | 5 | 角色扮演 | 创意写作、专业咨询 |
| **5C** | 5 | 契约式极简 | Token 敏感场景 |
| **CO-STAR** | 6 | 内容创作 | 营销文案、正式文档 |
| **RISEN** | 6 | 多步骤任务 | 复杂流程、项目管理 |

## 使用示例

### 基础版
```markdown
## Action
撰写一封面试感谢邮件

## Purpose
巩固面试官的良好印象，增加获得 offer 的概率

## Expectation
- 长度：150-200 字
- 语气：真诚、简洁
- 必须包含：对面试机会的感谢、一个面试亮点回顾、期待下一步
```

### 进阶版
```markdown
## Action
分析这份用户调研报告，识别 3 个核心痛点

## Purpose
为下个月的产品迭代优先级决策提供依据

## Expectation
- 输出格式：带编号的痛点列表，每个痛点包含：
  - 痛点描述（1-2 句）
  - 影响用户数量估算
  - 建议的解决方案方向
- 数据来源：必须基于报告中的具体数据
- 优先级：按影响程度从高到低排序
```

## APE 变体

### 简化版：AP（行动-目的）
适用于简单快速任务：
```markdown
Action: 回复这封投诉邮件
Purpose: 化解客户不满，挽留客户
```

### 扩展版：APEC（行动-目的-期望-约束）
增加约束条件：
```markdown
Action: 设计团队团建方案
Purpose: 增强跨部门协作
Expectation: 半天时间，预算 500 元/人
Constraint: 必须包含户外活动选项，不超过 20 人参与
```

## 最佳实践

1. **Action 要动词开头**：使用强动词（撰写、分析、创建、审查）
2. **Purpose 回答"为什么"**：不要重复 Action，而是解释动机
3. **Expectation 尽量量化**：用数字、格式、字数等明确标准
4. **三要素缺一不可**：省略任一要素都会降低输出质量
